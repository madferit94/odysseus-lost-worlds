# 선택형 플레이 기록 (v16에서 추가)

[English](TELEMETRY-v16.md) · **한국어**

플레이 기록 수집은 v16에서 추가한 측정 기능입니다. 난이도, 피해량, 목숨, 힐 존, 필살기 수치는 바꾸지 않습니다. 현재 게임(v17)도 같은 사건과 항목을 사용하며, 기록하는 버전 값만 `v17`입니다.

## 이용자 선택

- 게임 위의 선택란은 기본 해제입니다. 선택한 다음 새 게임을 시작해야 기록합니다.
- 게임 도중 켜면 다음 새 게임부터 적용합니다. 해제하면 새 전송과 재시도를 멈춥니다. 이미 전송 중인 요청을 취소하거나 저장된 기록을 지우는 기능은 아닙니다.
- 게임마다 새 임의 번호를 사용하며 순위표의 브라우저 번호와 연결하지 않습니다. 이름, 이메일, IP, 전체 URL, 기기 정보는 분석 표에 저장하지 않습니다. 호스팅 서비스 자체 접속 기록과는 별개입니다.
- 조회수와 온라인 순위는 별도 기능입니다. 순위 등록은 여전히 선택 사항입니다.
- 원본은 최근 90일을 분석 대상으로 합니다. 90일이 지난 원본은 다음 기록 시작 요청 때 정리하므로, 아무도 플레이하지 않는 기간에는 정리가 늦어질 수 있습니다. 정해진 일정에 따라 자동 삭제하는 기능은 아직 없습니다.

## 기록 정의

| 사건 | 기록 시점 |
|---|---|
| game_start | 새 여정 시작. 난이도, 빌드 버전(현재 게임은 `v17`을 보내며 서버는 `v16`도 받습니다), 유입 분류, 테스트 여부를 `play_sessions`에 저장 |
| stage_start | 스테이지 입장 또는 사망 후 재개. `attempt`는 해당 스테이지의 시도 번호이며 0부터 시작 |
| stage_complete | 전투 종료, 프롤로그 통과, 에필로그 완료. 시도마다 한 번만 기록 |
| player_death / retry | HP가 0이 됨 / 남은 목숨으로 실제 재개 |
| boss_start / boss_end | 보스 시도 시작 / 승리 또는 사망으로 종료. `duration_ms`는 그 시도 동안 흐른 게임 시간 |
| finisher_ready | 에너지가 필살기 필요량 이상이 된 시점. 착지·연출 종료 등 모든 사용 조건이 갖춰졌다는 뜻은 아님 |
| finisher_use | 실제로 발동한 필살기만 기록. `energy`는 사용 직전 값(제우스 200) |
| game_clear / game_over | 에필로그 완료 / 목숨 3개 모두 소진. 순위 등록 여부와 관계없이 저장 |
| session_hidden / session_resumed | 페이지 숨김 / 복귀. 이탈이나 패배로 단정하지 않음 |

`active_ms`는 게임 자체 시계입니다. 일시정지와 사망 후 대기는 빼고, 전투 연출·컷신·에필로그는 포함합니다. 한 프레임에 더하는 시간에 상한이 있어 느린 기기에서는 실제 시간보다 짧을 수 있습니다. `received_at`은 서버가 받은 시각(UTC epoch 초)입니다. 마지막 사건 시각은 전체 플레이 시간의 하한입니다.

보스 시도는 사망 후 다시 시작하지만 적이 입은 피해는 남아 있습니다. 따라서 두 번째 시도는 체력이 가득 찬 새 보스전이 아닙니다. 첫 시도 성공률은 따로 비교하세요. 준비 사건은 에너지 기준만 측정하며 모든 사용 조건을 뜻하지 않습니다.

## 유입 링크

공개 게임 주소 뒤에 `?utm_source=x`, `?utm_source=reddit`, `?utm_source=linkedin`, `?utm_source=itch`를 붙입니다. `twitter`는 `x`로, `itch.io`는 `itch`로 저장하고 그 밖의 값은 `other`로만 저장합니다. 매개변수가 없으면 `direct`로 분류하지만, 실제로 주소를 직접 입력했다는 증거는 아닙니다. 전체 URL이나 referrer는 저장하지 않습니다.

이 기능은 **동의하고 게임을 시작한 이후**의 유입별 진행 분석을 지원합니다. 채널별 전체 방문 수, 동의하지 않은 사람, 순 방문자 수, 재방문율은 측정하지 않습니다. 조회수와 나누어 정확한 유입 전환율처럼 해석하지 마세요.

## 전송 품질

- 한 번에 최대 10건, 게임당 최대 2,000건, 전송 대기 메모리 최대 500건입니다.
- 같은 게임 번호와 사건 순서로 다시 보낸 기록은 한 건만 저장합니다. 서버의 저장 확인을 받은 뒤에만 화면에 저장 완료를 표시합니다.
- 네트워크가 돌아오면 이어서 보내고, 간격을 두고 다시 시도합니다. 요청 제한 8초, 재시도 간격 최대 30초입니다. 오랜 오프라인, 강제 종료, 한도 도달 때는 기록이 빠질 수 있습니다. 시작한 지 24시간이 지난 여정은 새 기록을 받지 않습니다.
- 새로고침하면 아직 보내지 못한 기록은 복구하지 않습니다. 분석할 때 사건 순서 누락, 시작 사건 누락, 최종 결과 미확인을 따로 확인하세요. 종료 직전 마지막 사건이 빠진 경우는 순서 검사만으로 찾을 수 없습니다.
- 브라우저가 보고한 자료이므로 조작, 자동 방문, 스스로 표시한 테스트 여부를 완벽히 막지 못합니다. 이용자 행동을 이해하는 참고 자료로만 쓰고, 상금 정산 같은 판단에는 쓰지 마세요.

## 운영자 전용 CSV 내보내기

공개적으로 자료를 조회하거나 CSV를 내려받는 경로는 없습니다. **사이트 소유자의 인증된 Sites DB 조회**로만 읽고, CSV는 내 컴퓨터에서 만듭니다. 플레이어에게 원본을 보여주지 않습니다.

1. 소유자 연결로 DB 구조를 확인한 뒤 `play_sessions`, `play_events`의 모든 페이지를 읽습니다. 조회가 돌려준 다음 페이지 값만 사용합니다.
2. 토큰 해시를 빼고 `{complete:true,sessions:[...],events:[...]}` 형태로 `.analytics-private/` 아래 새 JSON 파일에 저장합니다. 읽는 동안에도 수집이 계속되므로 한 시점의 완전한 사본은 아닙니다. 시작 기록이 없는 사건이 있는지 다시 확인합니다.
3. `node export-analytics.mjs <snapshot.json> <새 출력 폴더>`를 실행합니다. 기본값은 `is_test=0`만 포함합니다. QA 확인 때만 `--include-tests`를 붙입니다.
4. `sessions.csv`는 여정별 요약, `events.csv`는 행동별 자료입니다. 이미 있는 출력 폴더에는 덮어쓰지 않습니다. 원본과 CSV는 Git에 올리지 않습니다.

`outcome=unknown`은 진행 중, 종료 미확인, 수집 중지를 모두 포함합니다. 모두 실패로 계산하지 마세요. `missing_sequences`, `has_start`, `terminal_conflict`로 자료 상태를 확인하고, 버전·난이도·테스트 여부를 나누어 분석합니다. 전후 비교는 관찰 자료이며 원인과 결과를 확정하지 않습니다.

## 검사 명령

게임 폴더에서 Node.js 24 이상으로 `npm test`(`node test-game.cjs`와 `node --test test-worker.mjs test-telemetry.mjs test-display.mjs` 실행), 배포용 Worker를 만드는 `node build.mjs`를 실행합니다.
테스트 플레이는 `?test=1` 주소로 열고 동의한 뒤 시작합니다. 자동 시뮬레이션과 실제 브라우저 수동 플레이는 구분해서 기록합니다.
