# 게임 폴더 안내

[English](README.md) · **한국어**

이 폴더에는 브라우저 게임과 서버 코드가 있습니다. 게임 소개와 조작법은 [프로젝트 소개](../README.ko.md)에서, 버전별 변경 사항은 [업데이트 내역](../CHANGELOG.ko.md)에서 확인할 수 있습니다.

## 폴더 구성

| 경로 | 하는 일 |
| --- | --- |

## 내 컴퓨터에서 실행하기

컴퓨터 브라우저에서 `index.html`을 엽니다. 게임을 보고 플레이하는 데에는 설치가 필요 없습니다.

**온라인 순위·조회수·플레이 기록은 공개 사이트의 서버와 데이터베이스가 있어야 동작합니다.** 파일을 직접 열거나 다른 웹 호스팅에 올리면 게임은 실행되지만, 이 기능들은 불러오거나 저장하지 못합니다.

## 검사와 빌드

이 폴더에서 Node.js 24 이상으로 실행합니다.

```sh
npm test          # 게임·화면·서버·플레이 기록 검사
node build.mjs    # 배포용 게임과 서버를 dist/에 만듭니다
```

`npm test`는 `npm install` 없이 실행됩니다. `dist/`는 빌드 결과물이라 Git에 올리지 않습니다. `node build.mjs`는 기존 공개 사이트 프로젝트를 가리키는 `.openai/hosting.json`을 읽습니다. 다른 계정에서 배포하려면 자신의 프로젝트와 데이터베이스를 따로 준비해야 합니다.

## 보스 연습 (v19)

`practice.js`는 이 브라우저가 어느 여정에서든 물리친 보스를 `localStorage`(키 `odysseus-bosses-beaten-v1`)에 기억합니다. 보스 연습 메뉴는 보스 4명을 보여 주며, 아직 이기지 않은 보스는 잠겨 있고, 하나도 없으면 여는 방법을 안내합니다.

- 연습은 선택한 난이도로 `enter()`를 통해 그 보스 스테이지를 시작합니다. 도착했을 때의 상태를 씁니다: 최대 체력 100 + 앞선 보스마다 20, 그 보스들의 축복, 그 스테이지의 공격력 보너스, 무기 1, 게이지 0, 목숨 1개.
- 보스가 쓰러지면(다음 장면이나 스테이지로 넘어가지 않음) 또는 처음 쓰러지면 끝납니다. 메뉴가 승리·패배, 보스, 난이도, 게임 시간을 보여 주고 다시 고를 수 있게 열려 있습니다.
- **순위 제외, 체크포인트 유지.** 연습은 순위용 기록을 시작하지 않고, 이 페이지가 전에 시작한 기록도 버리며, 연습으로 표시된 요청은 서버가 거절합니다. `checkpoint.js`는 새 여정과 이어한 여정에서만 저장하므로 연습은 이어하기 체크포인트를 쓰거나 지우지 않습니다.
- 완주한 순위 결과가 닉네임 입력을 기다리는 동안에는 연습 버튼을 끄고 안내(한국어·영어)를 보여 줍니다. 결과를 저장하거나 순위 입력란의 ‘저장하지 않고 건너뛰기’를 누르면 다시 쓸 수 있습니다. 그렇지 않으면 연습을 시작할 때 그 결과가 사라지기 때문입니다.
- 선택형 플레이 기록: 연습은 `mode` = `practice`인 별도 기록이며, 이기면 `game_clear`, 지면 `game_over`로 끝납니다.

## 체크포인트에서 이어하기 (v19)

`checkpoint.js`는 스테이지 1~9가 시작될 때마다 브라우저의 `localStorage`(키 `odysseus-checkpoint-v1`)에 체크포인트를 저장합니다. `game.js`가 다음 스테이지로 넘겨주는 값만 저장합니다: 스테이지, 난이도, 목숨, 최대 체력(보스 축복), 필살기 게이지, 방패(최대 60, `enter()`가 초기화하지 않음), 무기, 이긴 보스, 천상의 나침반, 점수, 처치 수와 여정 누적 수치. 스테이지가 시작될 때마다 체력이 가득 차므로 체력은 저장하지 않습니다. 그래서 이어한 스테이지는 처음 시작될 때와 같은 주인공·여정 상태로 시작하며, 게임 시간만 다시 셉니다.

- 이어하기 버튼은 올바른 체크포인트가 있을 때만 시작·게임 오버·엔딩 화면에 나타납니다. 저장한 상태를 넣고 게임이 쓰는 `enter()`로 그 스테이지를 시작하며, 난이도는 선택 버튼이 아니라 저장한 난이도를 씁니다. 게임 시간은 0부터 다시 셉니다.
- 게임 오버가 되어도 체크포인트는 남습니다(그 스테이지 시작 시점, 그때의 목숨). 집에 도착하면 지웁니다. 새 게임은 새 여정이 스테이지 1에 들어갈 때 체크포인트를 바꿉니다. 프롤로그에는 전투가 없어서, 실수로 Enter를 눌러도 저장한 여정을 바로 잃지 않습니다.
- 저장 오류(차단, 용량 부족, 사생활 보호 모드)는 잡아내며, 그럴 때는 이어하기 없이 게임만 동작합니다. 게임 규칙과 맞지 않는 체크포인트(예: 이긴 보스보다 많은 최대 체력)는 무시하고 지웁니다.
- **순위 제외.** 이어한 여정은 순위용 기록을 시작하지 않고, 이 페이지가 전에 시작한 기록도 버리며, 닉네임 입력란을 보여 주지 않습니다. 서버도 `mode`가 `normal`이 아닌 `POST /api/runs`, `POST /api/results`를 거절합니다(`400`, `unranked_mode`). 서버는 게임 화면을 볼 수 없으므로, 고친 브라우저가 꾸민 결과를 일반 여정처럼 보내는 것은 막을 수 없습니다. 이는 순위 보호에 적은 한계와 같으며, 그런 기록은 운영자가 지웁니다.
- 선택형 플레이 기록: 이어한 여정은 `mode` = `continue`인 새 기록으로 남습니다([플레이 기록 안내](TELEMETRY-v16.ko.md)).

## 난이도별 순위 (v18)

난이도마다 순위표가 따로 있습니다. 페이지에는 난이도 탭 4개와 ‘이전 기록’ 탭(난이도가 기록되지 않은 결과)이 있습니다.

- 게임을 시작할 때 페이지가 고른 난이도를 시작 요청에 함께 보냅니다(`POST /api/runs`, 내용 `{"difficulty":"trial"}`). 서버는 값이 `ithaca`, `aegean`, `trial`, `wrath` 중 하나인지 확인하고 `runs.difficulty` 칸에 저장합니다. 알 수 없는 값은 거절합니다(`400`, `invalid_difficulty`).
- 끝날 때 보내는 결과에는 난이도가 없습니다. 요청에 난이도가 들어 있어도 서버는 무시하며, 게임 시작 기록이 순위표를 정합니다. 아래의 닉네임·브라우저 확인·결과 검사는 그대로입니다.
- `GET /api/leaderboard?difficulty=ithaca|aegean|trial|wrath|legacy`는 순위표 하나(상위 20개와 그 순위표에서 내 최고 기록)를 돌려줍니다. 값이 없으면 예전처럼 모든 결과를 합친 목록을 예전 형식으로 돌려주므로, 업데이트 전에 열어 둔 페이지도 동작합니다.
- **난이도가 기록되지 않은 결과(`legacy`): v18 이전 기록 또는 업데이트 전에 열어 둔 페이지로 시작한 게임.** v18 이전에는 `runs` 표에 난이도를 저장하지 않았고, 선택형 플레이 기록은 동의한 경우에만 따로 저장되며 순위 기록과 연결되어 있지 않습니다. 그래서 예전 결과의 난이도는 알 수 없습니다. 보통 난이도로 가정하지 않고 난이도 칸을 비워 둔 채 ‘이전 기록 (난이도 구분 전)’에만 보여 줍니다. 업데이트 전에 열어 둔 페이지로 시작한 게임(난이도를 보내지 않음)도 여기에 들어갑니다.
- 한계: 결과의 다른 값과 마찬가지로 난이도도 게임 시작 때 플레이어의 브라우저가 알려 줍니다. 서버는 실제로 그 난이도로 플레이했는지 확인할 수 없습니다.
- 데이터베이스 변경: `drizzle/0004_runs_difficulty.sql`은 칸 하나와 색인을 추가하기만 합니다. 기존 기록과 칸은 바꾸지 않습니다.

## 순위 보호

게임 결과는 플레이어의 브라우저가 서버에 알려 주며, 서버는 실제 플레이를 볼 수 없습니다. 아래 검사는 실제 게임으로는 나올 수 없는 결과를 거절하고, 자동 스크립트로 반복하는 악용을 늦춥니다. 조작을 완전히 막지는 못합니다. 그럴듯하게 꾸민 결과(100초 이상, 맞는 적 수)는 저장될 수 있으므로, 그런 기록은 운영자가 직접 지웁니다.

**결과 검사** (`server/protection.mjs`). 거절된 결과는 오류 메시지를 받고 순위에 오르지 않습니다.

- 플레이 시간은 서버가 본 게임 시작 이후 시간보다 10초 넘게 길 수 없습니다.
- 플레이 시간은 **100초 이상**이어야 합니다. 이 값을 정한 방법:
  - 싸움을 전혀 하지 않아도 정해진 구간에만 최소 약 53초가 걸립니다. 시작 직후 1.4초 정지, 초당 205px로 약 4,100px 이동, 웨이브 사이 1.25초 대기 7번, 이야기 장면 15초, 마지막 장면 8초입니다. 실제 게임 코드에서 적이 나오자마자 모두 없애도록 돌렸을 때 69초가 걸렸습니다.
  - 실제 게임 코드를 돌리며 가장 가까운 적을 공격하고 필살기를 쓰고 피하지 않는 자동 플레이(봇)는 가장 쉬운 난이도를 무기 3종과 여러 필살기 선택으로 175~210초에 끝냈습니다(네 난이도 전체는 175~212초). 실제 플레이어는 공격을 피해야 하므로 더 오래 걸립니다.
  - 100초는 봇의 가장 빠른 기록의 약 57%입니다. `test-plausibility.mjs`가 검사할 때마다 봇을 다시 돌리고, 기준이 봇 최고 기록의 60%를 넘으면(예: 밸런스 변경 뒤) 실패합니다.
- 적 수는 게임과 맞아야 합니다. 일반 적 72~74명(웨이브 12번 × 6명, 그리고 안티노오스 전투의 호위 2명은 세지 않고 사라질 수 있음)과 보스 정확히 4명입니다. `test-plausibility.mjs`가 `game.js`의 스테이지 정보로 이 수를 다시 셉니다.
- 재도전하려면 먼저 쓰러져야 하고, 첫 목숨의 HP는 정확히 100입니다. 재도전이 있는데 받은 피해가 100 미만이면 거절합니다.
- 아직 검사하지 않는 것: 게임 규칙상 재도전은 최대 2번(목숨 3개)이고 재도전마다 피해 100 이상이 필요합니다. 기존의 재도전 상한(999번)을 그대로 두기로 해서 넣지 않았으며, 추가 여부는 운영자가 정합니다.

**닉네임** (`server/nickname.mjs`). 검사와 저장 전에 닉네임을 정규화합니다(전각·장식 글자를 보통 글자로, 예: `Ｈｅｒｏ` → `Hero`). 앞뒤 공백을 지우고 여러 칸 공백은 한 칸으로 줄입니다. 쓸 수 있는 글자는 그대로입니다(글자, 숫자, 공백, 점, 대시, 밑줄, 최대 16자). 그다음:

- 금지 목록의 이름은 거절합니다. 흔한 영어·한국어 욕설과 혐오 표현입니다. 공백·점·대시·밑줄은 무시하고, 비슷하게 생긴 문자는 글자로 읽습니다(`0`→o, `1`→i 또는 l, `3`→e, `4`→a, `5`→s, `@`→a, `$`→s, 라틴 글자처럼 보이는 키릴·그리스 글자).
- 예약 이름은 거절합니다. admin, moderator, system, odysseus 같은 이름과 운영자, 관리자입니다. 숫자를 붙이거나(`admin01`) 다른 단어와 띄어 써도(`Game Admin`) 거절합니다.
- 라틴 글자와 키릴·그리스 글자를 섞은 이름은 거절합니다(비슷하게 생긴 이름을 만드는 흔한 방법).
- 목록은 `server/nickname-blocklist.mjs`에 있으며 여기서 고칩니다. 기본 필터일 뿐 완전한 검열은 아닙니다. 놓치는 표현이 있고, 금지어가 들어 있는 평범한 이름을 거절할 수도 있습니다(예: "Scunthorpe"). 이를 줄이려고 일부 단어는 이름 전체가 그 단어일 때만 막습니다(예: "dick"은 막고 "Dickens"는 허용).

**요청 횟수 제한**. 접속 주소 하나당 10분에 새 게임 30번, 순위 등록 20번, 조회수 기록 60번, 플레이 기록 시작 30번, 플레이 기록 묶음 300번까지 받습니다. 넘으면 `429`와 기다릴 초를 담은 `Retry-After` 헤더로 답합니다. 값은 `server/protection.mjs`의 상수입니다.

- 횟수는 서버 인스턴스 하나의 메모리에만 저장합니다. 호스팅이 인스턴스를 여러 개 돌리면 각각 따로 세고, 재시작하면 초기화됩니다. 최선의 노력일 뿐이므로, 호스팅이 플랫폼 수준의 요청 제한 규칙을 제공하면 함께 쓰는 것을 권합니다.
- 주소는 `cf-connecting-ip`, 없으면 `x-real-ip`, 없으면 `x-forwarded-for`의 마지막 값을 씁니다. 셋 다 없는 요청은 한 묶음으로 세고 한도를 10배로 둡니다.
- 선택형 플레이 기록은 `429`를 일시적인 오류로 보고 나중에 다시 보냅니다. 게임은 영향을 받지 않습니다.

**조회수**는 브라우저가 이 사이트에서 보낸 요청이라고 표시할 때만 셉니다(`Origin`이 이 사이트이거나 `Sec-Fetch-Site: same-origin`/`same-site`). 브라우저는 이 요청에 항상 이 헤더를 보냅니다. 둘 다 없는 요청은 현재 조회수만 돌려받고 세지 않습니다. 다른 사이트에서 온 요청은 거절합니다. 스크립트는 이 헤더를 꾸밀 수 있으므로, 부풀리기를 실제로 막는 것은 요청 횟수 제한입니다.

**정리**. 새 게임을 시작할 때, 24시간 전에 시작했지만 등록하지 않은 게임 기록을 지웁니다. 서버 인스턴스마다 10분에 한 번까지만 합니다. 따라서 24시간 넘게 멈춰 둔 게임은 순위에 등록할 수 없습니다.

### 순위 기록 지우기

`admin-remove-run.mjs`는 게임 ID나 닉네임으로 기록을 찾습니다(닉네임은 대소문자와 여분의 공백을 무시). `--confirm`을 붙이지 않으면 찾은 기록을 보여 주기만 합니다.

```sh
# 데이터베이스의 SQLite 사본(예: 내 컴퓨터의 개발용 데이터베이스)
node admin-remove-run.mjs --db ranking.sqlite --nickname "Cheater"            # 목록만
node admin-remove-run.mjs --db ranking.sqlite --nickname "Cheater" --confirm  # 삭제

# 공개 사이트 데이터베이스: 사이트 소유자의 인증된 Sites 데이터베이스 연결로
# runs 표를 읽어(플레이 기록 안내와 같은 방식) .analytics-private/ 아래에
# {"complete":true,"runs":[...]} 형태로 저장한 뒤
node admin-remove-run.mjs --snapshot .analytics-private/runs.json --run <게임-ID> --confirm
```

`--snapshot`을 쓰면 내 컴퓨터에서는 아무것도 지우지 않습니다. `--confirm`은 같은 소유자 연결로 실행할 `DELETE` 문을 출력합니다.
